# 出处纪律（短版）

Kernoscope 的核心不变式：**每个数字都带出处，出处不同就不能混用**。
完整规则见仓库的 `PROVENANCE.md`；这里是 agent 需要的最小集。

## 五个标签

| 标签 | 前缀 | 含义 | 能怎样用 |
|---|---|---|---|
| `exact` | `launch__*` / `gpu__time_duration*` / `ks__cubin_*` | 与 ncu 同源：CUPTI activity 的时长与配置、cubin 的静态属性 | 可以当事实引用 |
| `measured` | `meas__*` | 我们的探针/NVML 的**原始读数**（能量、时钟、显存忙碌占比、区间重叠重建的 occupancy） | 可以当测量值引用，但要带分辨率 |
| `estimated` | `est__*` / `model__*` | 代理或模型推算（DRAM 字节代理、roofline、L2 命中模型、发射槽上界） | 必须与误差带、前提一起引用 |
| `derived` | `ks__*` | 由实测**再算出来**的统计量/判词（覆盖率、份额、误差百分比） | 引用时要能追到它的输入 |
| `unavailable` | 任意（含计数器命名空间） | 拿不到：报 `n/a` + 结构化拒绝 | **不能**当 0 或"没有影响" |

## 三条容易踩的

1. **分辨率**：`utilization.memory` 是整数百分比（1 个百分点）＋ 200 ms 采样周期。
   读数为 `0.0%` 时"真的是 0"与"被截断成 0"不可区分 —— 此时工具拒绝给字节数。
2. **单边偏高**：DRAM 代理在高负载下系统性偏高（真机误差带约 −4% ~ +10%）。
   不要说"两次方向一致所以可信"。
3. **命名纪律**：`meas__` 承诺"这是实测读数"、`est__` 承诺"这是推算"。
   看到 `meas__` 就可以当测量值；看到 `est__` 必须找前提与误差带。

## 反例（agent 最常犯）

- 把 `est__dram_bytes_per_launch` 当作"这个 kernel 搬了多少字节"的事实 ——
  它是**代理**，且只有在窗口被该 kernel 主导（前提成立）时才成立。
- 把 `n/a` 读成 0，于是得出"DRAM 没有瓶颈"。
- 忽略 `status`：前提 `ok=false` 的判词即使有数值也不可引用（v1.1 起 `actionable=false`）。
